# FSP Catalyst Connect 3.0 — Landing Page

A conversion-focused landing page for **FSP Catalyst Connect 3.0**, a community
gathering for trainers, facilitators, coaches and L&D professionals.

**Chennai, India — Sunday, 22 November 2026.**

---

| Concern    | Choice                                        |

### Palette

Taken directly from the FSP Catalyst Connect logo:

| Token                | Value     | Use                                    |
| -------------------- | --------- | -------------------------------------- |
| `--color-navy`       | `#0F1940` | logo navy; type sitting on amber       |
| `--color-accent`     | `#FAA81C` | logo amber — buttons, rules, emphasis  |
| `--color-ink`        | `#080D20` | page canvas (deepened navy)            |
| `--color-surface-2`  | `#141B3C` | raised cards                           |
| `--color-cream`      | `#F7F3ED` | warm white body type                   |
| `--color-on-accent`  | `#0F1940` | label colour on amber fills            |

Amber is a light colour, so anything sitting **on** it uses navy, never white.
All tokens are defined in the `@theme` block of `src/app/globals.css`.

### Logo assets

Three files in `/public/brand/`:

| File                            | Use                                           |
| ------------------------------- | --------------------------------------------- |
| `logo-reversed.png`             | navy recoloured to warm white, amber kept — used on the dark canvas |
| `logo-colour.png`               | original colours, cropped — light backgrounds, email, print |
| `fsp-catalyst-connect-logo.png` | untouched original as supplied                |

The reversed variant was generated by recolouring only the navy pixels, leaving
the amber figure, star, divider and "Catalyst" exactly as drawn, with the alpha
channel preserved so edges stay clean. It scores **16.8:1** on the canvas; the
original navy would have scored 1.16:1 and been invisible.

The landing page is prerendered. Registration and payment verification use server-side API routes, so deployment requires a Node-capable Next.js host.

See [PAYMENT-SETUP.md](./PAYMENT-SETUP.md) for Razorpay and Google Sheets configuration.


### Browser verification

Run `npm run audit` or `npm run verify` while the site is running. Both commands use the same checks.

The suite checks installed Windows Edge and Chrome across seven screen widths, plus reduced motion, JavaScript-disabled content visibility, and enlarged text. It exercises FAQ mouse/keyboard controls and video activation, and checks layout overflow, image loading, and section links. Reports and screenshots are saved in `artifacts/audit/`.

Use `VERIFY_URL` to target another port; the default is `http://localhost:3001`. See [WEBSITE-AUDIT.md](./WEBSITE-AUDIT.md) for production verification commands and remaining launch requirements.

## Deploying

The project is a standard Next.js app and deploys unchanged to Vercel:

```bash
npx vercel          # preview
npx vercel --prod   # production
```

For any Node host: `npm run build` then `npm run start` (defaults to port 3000,
override with `PORT`).

Before going live, set `seo.siteUrl` in `src/config/site.ts` to the real domain
so Open Graph URLs resolve correctly.

## Hero video

The hero centrepiece is the Catalyst Connect video
([youtu.be/nIEqBprksns](https://youtu.be/nIEqBprksns)), configured in
`video` in `src/config/site.ts`.

It is a **click-to-load facade**, not a live embed. On page load the hero
renders a local poster image and a play button — no YouTube iframe, no
third-party scripts, no cookies. The player is injected on first click.

This means:

- nothing is sent to YouTube until the visitor chooses to watch (verified in
  `npm run verify`: *third-party requests before click: 0*)
- the hero's largest element is a local, `priority`-loaded, Next-optimized
  image rather than a ~1MB player bundle
- the iframe uses `youtube-nocookie.com` once it does load

### Changing the video

Set `video.id` in the config, then refresh the poster so it matches:

```bash
curl -s "https://i.ytimg.com/vi/<NEW_ID>/maxresdefault.jpg" \
  -o public/video/catalyst-connect-poster.jpg
```

Update `video.title` too — it is used as the iframe title and the play
button's accessible name.

## Accessibility

- Semantic landmarks (`header` / `main` / `footer` / `section`), one `h1`, one
  `h2` per section.
- Skip-to-content link as the first focusable element.
- Visible focus ring (`:focus-visible`) on all interactive elements.
- FAQ accordion uses `aria-expanded` / `aria-controls` with a labelled region.
- Mobile menu exposes `aria-expanded`, closes on `Escape`, and locks background
  scroll while open.
- The mobile sticky bar is `inert` and `aria-hidden` while off screen, so it
  never traps focus.
- Decorative gradients and icons are `aria-hidden`.
- `prefers-reduced-motion` is honoured in **both** CSS and JS — `Reveal` and
  `HeroAccent` render final-state immediately rather than animating, and no
  content is gated behind an animation.
